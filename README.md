## 0.9.9 三模块独立防漏

一次AI回复分别解析三项。每个模块在格式验证、内容保存并回读成功后独立标记成功；单项失败不会阻止其他合法部分保存，也不推进该项进度。隐藏的模块进度条目记录成功、失败区间和最近错误；不注入模型。界面按1开始显示连续完成楼层、成功区间、缺口与失败区间；支持刷新进度（不调用AI）、单项补漏以及选定楼层重做。仅承接0.9.8明确“三个模块均成功”记录，且与时间线、关系范围交叉吻合的楼层；其他旧进度及正文“前N楼”标记不推断为成功。批量更新改为查缺补漏，三项均完成的楼层跳过；部分缺失只请求缺失项，100楼完成后续接101楼。正常更新仍每批一次AI，补漏每批一次且无自动重试。

## 0.9.8 每批一次 AI 统一生成

自动阈值、最近更新、指定楼层及批量更新统一使用一次请求，同时返回角色/主角档案、时间线增量、关系增量，再分别写入原固定条目。本轮聊天只发送一次。三部分先全部验证再保存，格式错误时停止本批，不自动追加请求或自动重试；用户可手动重做。单独时间线/关系按钮仍为手动补漏入口，各自才使用独立请求。批量每批一次，处理五批即五次正常请求。

## 0.9.7 关系增量覆盖记录

关系汇总独立记录已处理楼层，单独更新时分批补齐所有未处理范围；角色更新时重新检查选定范围。只有解析、保存与服务端回读全部成功才记录覆盖范围。空增量保留旧关系，关系变化覆盖对应关系。时间线仍独立增量更新、保留旧事件并追加新事件。

## 0.9.6 角色关系汇总

更新角色时独立调用关系增量请求，在主世界书按聊天维护唯一“角色关系汇总”条目。格式如“A ↔ B：同班同学、情侣”“B ↔ C：互相讨厌”“A → C：暗恋”。未变化关系保留，关系变化覆盖旧关系，单向与双向区分；新增单独更新按钮与结果预览。包含0.9.5时间线独立提示词与诊断。自动测试使用模拟宿主和模型，未在用户实际酒馆验证。

## 0.9.5 时间线增量提示词（待实际酒馆验证）

新增可编辑的“时间线增量提示词”，独立于角色全量/增量提示词保存、恢复并用于每次时间线请求。补充明确的“单独增量更新时间线”按钮与本次调用详情（楼层、原始回复、解析/去重条数、UID）。默认提示词包含关键关系与行动进展，不再只接受重大转折；同一人物的后续进展仍需追加。保存后从服务端回读确认内容，回读不一致时报错。

验证：`node --experimental-vm-modules --test *.test.mjs`。覆盖原有回归、连续三轮追加、空结果重试、实际模块从设置按钮到 API 包装与保存回读的模拟联调。AI 返回与酒馆宿主由测试模拟，未在用户实际酒馆及模型中验证。

## 0.9.4 时间线增量修复

角色更新时重新检查本次选定范围，不再因已有覆盖标记跳过；无角色档案变更时仍独立更新时间线。独立刷新会补齐历史缺口并重新检查最近一批，允许补回此前空结果或重生成后的事件。已有时间线持续保留、完全相同事件去重，仍保存为单条目。刷新状态显示新增事件数。

## 0.9.3 时间线更新

每个聊天的主线时间线固定保存到同一条目。点击刷新时间线或更新角色档案时，自动合并本聊天原有的分批时间线、去除完全重复的事件，并保留各段已处理楼层记录；不同聊天独立保存。旧条目合并与删除在同一次世界书保存中完成。

# 角色世界书（系统 API 版）

这是对 ST-Amily2-Chat-Optimisation 中 Character World Book 逻辑的独立复刻版。它直接调用 SillyTavern 当前连接的系统 API，不需要单独填写 API URL、密钥或模型。

## 安装

将整个 `cwb-system-api` 文件夹放入：

`SillyTavern/data/<你的用户目录>/extensions/`

重启 SillyTavern 或刷新页面。设置面板中会出现“角色世界书（系统 API 版）”。使用前请先为当前角色绑定主世界书，或者在插件设置里选择指定世界书。

## 已复刻功能

- 当前聊天内容提取与角色档案生成
- 全量模式、增量融合旧档案
- 每个角色一个选择性世界书条目
- 按聊天 ID 隔离并自动启停相关条目
- “Amily2角色总集”常驻条目与已更新楼层记录
- 最近若干层、指定楼层、全聊天分批更新
- 按消息阈值自动更新
- 原版 `[--Amily2::CHAR_START--]` 数据格式与旧格式转换
- 角色档案查看、编辑和删除

## 编辑角色生成提示词

在酒馆右侧“扩展”面板展开“角色世界书（系统 API 版）”，即可看到“角色信息生成提示词”区域。这里可以直接编辑前置系统提示词、全量生成提示词和增量融合提示词；输入内容会自动保存，下一次点击更新时生效。字段定义和输出格式也包含在全量/增量提示词中，可以直接一并修改。点击“恢复默认提示词”可撤销自定义内容。

## 多故事线世界书

勾选“自动分配到对应故事线世界书”后，插件会扫描酒馆中的世界书，根据条目关键词和内容中的 `name` 字段识别角色归属。生成的角色档案会写入对应世界书中的独立 `CWB:自动档案` 条目，不覆盖原有手工角色设定。若同名角色存在于多本世界书，可在“手动角色绑定”中填写 JSON 覆盖自动识别，例如 `{"许亦宁":"故事线01"}`。新增或导入故事线世界书后，点击“扫描世界书角色归属”即可刷新识别结果。

启用多世界书路由后，插件还会在当前角色卡绑定的主世界书中维护一个 `CWB角色世界书档案目录-聊天ID` 条目。目录只记录角色名、所属故事线世界书和自动档案位置，供模型快速定位，不会复制完整角色档案。

v0.5 默认提示词只维护三类信息：`SEX` 性经历事实摘要与次数、`DY/REL` 对用户的好感度等动态数值及变化依据、`PL` 当前剧情条目。外貌、服装、性格、背景、语言风格、身体细节等静态字段不再生成。所有提示词仍可在插件设置中继续编辑。

用户主角使用 `[record_type]:USER` 独立输出，并固定保存到当前角色卡绑定的主世界书中。所有自动生成档案统一按 `动态-名字` 命名，例如 `动态-许亦宁`、`动态-赵冠宇`。主角档案维护自身状态、目标、能力、资源、经历、关系网络和参与的剧情条目，不参与普通角色的故事线世界书路由。

启用插件后，“角色档案”按钮固定显示在酒馆顶部设置图标栏的最右侧，位于扩展（方块）图标之后，点击即可查看、编辑或删除当前聊天的自动档案。

## API 行为

内部使用 SillyTavern 原生 `generateRaw()`，因此会沿用当前主 API、当前模型、采样预设和 instruct 状态。插件只允许可选地限制最大回复 Token，不保存任何 API 密钥。
